# AEO 파일럿 인수인계 (대표님용)

- 작성일: 2026-10-29
- 이 폴더의 다른 파일: `README.md`(설계·판정 기준), `prompt-panel.csv`(질문 20개), `measurement-log.csv`(기록 양식), `change-log.md`(변경 이력)

## 0. 한 줄 요약

설계 문서와 양식은 준비되어 있습니다. **측정을 시작하기 전에 정할 것이 5가지 남아 있습니다.** 이것이 정해지지 않으면 결과를 영업 근거로 쓰기 어렵습니다.

## 1. 10/31까지 정할 것 (중요한 순서)

| # | 결정 사항 | 왜 중요한가 | 권장 |
|---|---|---|---|
| 1 | **측정 담당자와 작업량 방식** | 측정 1회 = 질문 20개 × 엔진 3개 × 5회 = 응답 300건. 수동으로는 5시간 이상 걸림 | 담당자를 먼저 정하고, 시간이 부족하면 반복 횟수를 줄이는 쪽(README 5절 b)으로 정한 뒤 고정 |
| 2 | **개입 내용** (현재 대기) | 나리보는 이미 10/09에 게재됨. 개입이 없으면 "전후 비교"가 성립하지 않음 | 개입이 계속 없으면 **아직 진사이트에 올리지 않은 신규 고객사**를 파일럿 대상으로 바꾸는 것이 영업 근거로 가장 깔끔함 |
| 3 | **대조군 1~2곳** | 엔진 자체가 바뀌어서 생긴 변화와 구분하려면 필요 | 10/30에 카테고리 질문을 한 번씩 돌려 보고, 답변에 나오는 소형 동종 서비스 중 선택 (README 2절) |
| 4 | **측정 요일·시간대, 엔진 계정·설정** | 조건이 달라지면 회차끼리 비교 불가 | 예: 매주 화요일 오전, 같은 계정, 웹 검색 켠 상태 |
| 5 | **프롬프트 20개 최종 검토 후 동결** | 확정 후에는 한 글자도 바꾸지 않아야 함 | 나리보 서비스 설명이 맞는지 나리보 측에 한 번 확인 |

**1~3번이 10/31까지 정해지지 않으면, 기준선 시작을 11/1에서 1주 미루는 것을 권합니다.**
조건이 흔들린 상태로 시작한 기준선은 나중에 쓸 수 없고, 일정을 1주 미루는 비용이 더 작습니다. 미루면 README 7절 일정도 같이 고쳐 주세요.

## 2. 매 측정 회차 절차

1. `change-log.md`를 먼저 봅니다. 지난 회차 이후 진사이트·나리보·대조군 사이트에 바뀐 것이 있으면 기록합니다.
2. 엔진별로 질문을 실행합니다. **매번 새 대화**로 시작하고, 이전 대화 기록·메모리 기능은 꺼 둡니다.
3. 답변마다 `measurement-log.csv`에 기록합니다. 한 답변에 나리보와 대조군이 있으면 대상별로 행을 나눕니다.
   - 진사이트 링크 인용과 나리보 자체 사이트(narrivo.io) 인용은 **따로** 적습니다.
   - 답변 원문은 반드시 남깁니다. 나중에 판정을 다시 확인할 근거입니다.
4. 구글 AI 개요와 네이버 AI 답변은 주 1회만 확인하고, 엔진 열에 구분해서 적습니다.
5. 기록한 행은 고치지 않습니다. 실수가 있으면 새 행에 정정 내용을 적습니다.

## 3. 결과를 볼 때 하지 말 것

- **판정 기준(README 6절)을 결과를 본 뒤에 바꾸지 않기.** 바꾸면 결과를 영업 근거로 쓸 수 없습니다.
- **브랜드 질문과 카테고리 질문 결과를 합치지 않기.** 브랜드 질문("나리보는 어떤 서비스야?")은 원래 인용이 잘 되므로, 합치면 수치가 부풀려집니다.
- **"진사이트 덕분에 늘었다"고 단정하지 않기.** 대상이 1곳이고 엔진 변화를 통제할 수 없으므로 "이 기간에 이런 변화가 관측됐다"까지만 말할 수 있습니다.
- **나리보 동의 전에는 실명·화면을 영업 자료에 쓰지 않기.** 현재 동의 여부는 미확인입니다.

## 4. AI 봇 방문 확인 (참고)

GPTBot, PerplexityBot, ClaudeBot 같은 AI 봇이 진사이트를 읽어 갔는지는 서버 로그로 볼 수 있지만, 지금 상태로는 한계가 큽니다.

- **Vercel 로그 보관 기간**(2026-08 기준 공식 문서): Hobby 1시간, Pro 1일, Enterprise 3일. Observability Plus를 켜면 30일(한 번에 최대 14일 조회)
  - **현재 요금제 확인 필요**: Vercel 대시보드 → 팀 Settings → Billing
- **코드 수정 없이**: Vercel 대시보드 Logs에서 요청 하나하나를 열면 User Agent(봇 이름)가 보입니다. 하지만 봇 이름으로 걸러 보는 기능은 없어 모아 보기는 어렵습니다.
- **장기 보관이 필요하면**: Pro 이상에서 Log Drains로 로그를 외부 저장소로 보내는 방법이 있습니다(유료 외부 서비스가 필요할 수 있음).
- **개발 작업이 필요한 방법**: AI 봇 방문만 골라 DB에 따로 쌓는 방식입니다. 필요하면 개발 쪽에 요청하세요. 단, **기준선 기간(측정 중)에는 사이트를 바꾸지 않는 것이 원칙**이므로 기준선 전이나 개입 시점에 맞춰야 하고, 바꾸면 `change-log.md`에 기록해야 합니다.
- 구글 AI 개요와 Gemini는 일반 구글 검색봇(Googlebot)으로 수집하므로 로그로 구분할 수 없습니다.

봇 방문은 "AI가 읽어 갔다"는 증거일 뿐 "답변에 인용됐다"는 증거는 아닙니다. 판정은 측정 기록으로만 합니다.

## 5. 알고 있어야 할 위험·가정

- **기준선 시점**: 나리보는 이미 게재된 상태라, 11월 기준선은 "게재 후" 시점입니다.
- **표본 크기**: 기준선 2주에 주 1회 측정이면 데이터가 2개뿐이라 변동 폭 추정이 약합니다. 가능하면 주 2회를 권합니다.
- **대조군 후보 미검증**: 검색에서 커리어핏, 커리어리 같은 인접 서비스가 보였지만 규모·진사이트 게재 여부는 확인하지 않았습니다.
- **정확성 판정 기준**: 진사이트 프로필 내용(대표 황병엽, 2025-08 의왕시 설립 등)을 기준 사실로 썼고, 나리보에 직접 확인하지 않았습니다.
- **C05 질문**("무료로 써볼 만한 서비스")은 나리보의 무료 제공 여부를 모르는 상태에서 넣은 문항입니다. 검토 때 유지할지 정해 주세요.
- **엔진 쪽 변화**: ChatGPT·Gemini·Perplexity는 모델과 검색 방식이 예고 없이 바뀝니다. 알게 되면 `change-log.md`에 "엔진"으로 기록해 주세요.

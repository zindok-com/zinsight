# Agent Instructions (에이전트 행동 수칙)

## 1. 빌드 및 데이터베이스 마이그레이션 규칙
- **필요 시에만 빌드 실행**: 단순한 UI 마크업 변경, CSS 클래스 조정, 텍스트 수정과 같이 데이터베이스 스키마 구조 변경이나 엄격한 TypeScript 타입 인터페이스가 바뀌지 않는 사소한 마크업 작업 시에는 매번 전체 프로덕션 빌드(`pnpm build`)를 돌리지 마십시오.
- **마이그레이션 최소화**: 실서버 데이터베이스 마이그레이션 및 동기화는 데이터베이스 스키마 변경(`schema.prisma` 수정 등)이 있을 때만 명시적 근거 하에 선별적으로 구동하십시오.
- **개발 환경 위주의 검증**: 빌드나 작동 검증이 필요한 경우 가능하면 로컬/개발 환경 기준의 검증을 우선하고, 실서버용 변수가 들어간 빌드는 배포 전 마지막 완성 시점에 단 한 번 검증하거나 생략하십시오.

## 2. 데이터베이스 직접 수정 규칙
- **직접 실행 금지**: 에이전트가 DB 데이터를 직접 수정(INSERT / UPDATE / DELETE)하는 스크립트나 명령을 실행하지 마십시오.
- **보고만 수행**: DB 수정이 필요한 경우 필요한 SQL 쿼리를 정리하여 사용자에게 보고만 하십시오. 사용자가 직접 실행합니다.
- **스키마 변경은 별도**: `schema.prisma` 수정 후 마이그레이션(`prisma migrate`)은 위 1번 규칙에 따라 스키마 변경이 있을 때만 별도 판단하십시오.

## 3. 마이그레이션 적용 절차
- **운영 DB는 배포가 적용**: Vercel 빌드 명령이 `npx prisma migrate deploy && next build`이므로, 운영 DB(`.env`의 주석 처리된 DATABASE_URL)에는 배포 시 미적용 마이그레이션이 자동 적용됩니다. 마이그레이션 SQL을 운영 DB에 수동 실행하지 마십시오. 수동 실행 후 배포하면 `P3018`(중복 컬럼 등)로 배포가 막힙니다.
- **에이전트가 실행 가능한 명령**: 스키마 변경에 따른 `prisma migrate deploy`(개발 DB 적용)와 `prisma migrate resolve`(이력 복구)는 에이전트가 직접 실행할 수 있습니다. 대상 DB는 명령 실행 시 `DATABASE_URL`을 지정해 선택합니다.
- **운영 DB는 매번 확인**: 운영 DB를 대상으로 하는 마이그레이션 명령은 실행 전에 대상과 명령을 사용자에게 알리고 승인을 받은 뒤 실행하십시오.
- **데이터 변경은 2번 규칙 적용**: 마이그레이션이 아닌 데이터 입력·수정·삭제(초기 데이터 등록 등)는 SQL만 정리해 보고합니다.

## 4. Git 커밋 규칙
- **작업별 커밋 분리**: 변경/수정 사항이 여러 개일 경우 한 번에 묶지 않고, 반드시 기능 및 작업 단위별로 나누어 커밋하십시오.
- **한글로만 작성**: 모든 Git 커밋 메시지는 반드시 한글로만 작성하십시오.
